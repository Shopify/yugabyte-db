Phase 1-3 Yugabyte-side prototype

Yugabyte defines the index. QueryEngine maintains it later.

Externally maintained lazy indexes keep the normal YSQL secondary index table and planner integration, but remove index maintenance from the base-table write transaction. A serving lazy index can be used for fast reads with eventual-consistency semantics; strong reads exclude lazy indexes and use only Yugabyte-maintained indexes or the base table.

DDL

Create a normal YB LSM secondary index with WITH (yb_external_maintenance = true).

Writes

Base-table inserts, updates, and deletes skip externally maintained index tables.

Reads

eventual mode can use serving lazy indexes exactly like normal indexes.

Strong Mode

strong mode hides lazy indexes from planning, preserving strong query behavior.

System level

How it works

The key split is planner visibility, not special execution semantics. In eventual mode, a serving lazy index participates in normal planning. In strong mode, the same index is filtered out before path creation.

Read and write semantics

Expected behavior

Eventual is intentionally stale

The design accepts missing rows, stale rows, stale ordering, stale limits, stale aggregates, and stale join inputs whenever the chosen plan uses a lazy index.

This matches the product goal: remove index maintenance from the write transaction, then opt into the index for read acceleration when staleness is acceptable. 

CREATE INDEX lazy_idx
ON orders(status)
WITH (yb_external_maintenance = true);

-- Hidden until materialized.
ALTER INDEX lazy_idx SET (yb_lazy_index_serving = true);

-- Session-level planner policy.
SET yb_index_consistency = eventual; -- can use lazy indexes
SET yb_index_consistency = strong;   -- excludes lazy indexes
  • Lazy index creation is non-unique, non-primary, non-constraint, non-partitioned, and non-concurrent.
  • yb_external_maintenance is creation-time metadata and cannot be changed later.
  • yb_lazy_index_serving is the operator-controlled planner visibility flag.
  • Serving lazy indexes are not rechecked against the base table by default.

Planner Mode

Adds yb_index_consistency as a user-settable enum with eventual and strong modes.

  • Default is eventual for the read-optimization path.
  • strong provides a simple escape hatch for consistent reads.
  • Changing the mode resets the session plan cache so prepared statements replan.

Shared Helpers

  • YbIsExternallyMaintainedIndex validates YB LSM index state.
  • YbLazyIndexIsUsable applies consistency and serving gates.
  • yb_backfill_external_index supports the batch mock materializer.
src/postgres/src/backend/commands/indexcmds.c

Create Index

Validates lazy index DDL and changes create behavior for external maintenance.

  • Rejects unique, primary, constraint, exclusion, partitioned, and concurrent lazy indexes.
  • For lazy indexes, creates metadata and DocDB table but skips initial index build.
  • Forces lazy indexes to start non-serving.
src/postgres/src/backend/executor/execIndexing.c

Write Path

Filters externally maintained indexes out of ExecOpenIndices.

  • Base-table DML no longer opens lazy indexes for maintenance.
  • ri_NumIndices is reset after filtering so later executor loops see the reduced list.
src/postgres/src/backend/optimizer/util/plancat.c

Planner Gate

Filters indexes while collecting relation metadata for planning.

  • Non-serving lazy indexes are hidden.
  • Serving lazy indexes are visible in eventual mode.
  • All lazy indexes are hidden in strong mode.
src/postgres/src/backend/commands/tablecmds.c

ALTER Guards

Prevents metadata drift and invalidates plans when serving state changes.

  • yb_external_maintenance cannot be changed after index creation.
  • yb_lazy_index_serving=true requires yb_external_maintenance=true.
  • Serving flips invalidate the indexed base table's relcache so cached plans replan.

Batch materialization

Mock QueryEngine flow

Resolve the index

scripts/yb_lazy_index_mock_qe.py verifies the target exists and has yb_external_maintenance=true.

Mark non-serving

The script runs ALTER INDEX ... SET (yb_lazy_index_serving = false) so queries cannot plan the index while it is being populated.

Backfill from the base table

The script calls SELECT yb_backfill_external_index('schema.index'::regclass); to scan the base table and write index entries.

Flip serving

After the batch run, the script sets yb_lazy_index_serving=true, making the index eligible in eventual mode.

  --host 127.0.0.1 \
  --port 15433 \
  --user yugabyte \

Scope

What this prototype is and is not

In Scope

  • YSQL non-unique YB LSM secondary indexes.
  • Planner-level consistency control.
  • Write-path suppression for lazy indexes.
  • Batch materialization for end-to-end testing.
  • Normal index scans and pushdowns in eventual mode.
  • Plan-cache invalidation for consistency and serving-state changes.

Out Of Scope For This Phase

  • CDC or streaming maintenance.
  • Unique, primary, constraint, exclusion, and partitioned lazy indexes.
  • Guaranteed freshness in eventual mode.
  • Base-row validation as a safety rule.
  • Deleting stale index entries in the mock materializer.
  • Canceling already-running queries when an index is marked non-serving.
